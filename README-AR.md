# أسعار دكان العائلة — دليل الإعداد والنشر

هذا تطبيق ويب عربي يعمل على الهاتف والكمبيوتر. يسمح لأفراد العائلة المصرح لهم بتسجيل الدخول والبحث عن المنتجات وإضافتها وتعديل أسعارها أو حذفها. تخزن البيانات في Cloud Firestore وتتزامن مباشرة بين الأجهزة.

## الملفات
- `index.html`: هيكل الواجهة.
- `style.css`: التصميم المتجاوب RTL.
- `app.js`: تسجيل الدخول وإدارة المنتجات والمزامنة المباشرة.
- `firebase-config.js`: بيانات إعداد تطبيق Firebase للويب (املأ القيم قبل النشر).
- `firestore.rules`: قواعد أمان قاعدة البيانات. انسخها إلى قسم Firestore Rules بعد استبدال عناوين البريد التجريبية.

## A) إنشاء Firebase وربطه

1. افتح https://console.firebase.google.com/ وأنشئ مشروعًا جديدًا باسم مثل `family-shop-prices`.
2. من صفحة المشروع أضف تطبيق Web (أيقونة `</>`)، وسمّه `Family Shop Prices`.
3. انسخ كائن إعدادات Firebase الذي يظهر لك. افتح `firebase-config.js` واستبدل القيم التجريبية بقيم مشروعك:
   - `apiKey`
   - `authDomain`
   - `projectId`
   - `appId`
   - `messagingSenderId`
   يمكن ترك `storageBucket` خارج الملف لأن التطبيق لا يستخدم تخزين ملفات.
4. في Firebase افتح **Authentication → Get started → Sign-in method**، وفعّل **Email/Password**.
5. من **Authentication → Users → Add user** أنشئ حسابًا لكل فرد في العائلة. لا نضيف زر تسجيل عام داخل التطبيق حتى لا يسجل غرباء حسابات بأنفسهم. احتفظوا بكلمات المرور ولا تشاركوها مع أحد خارج العائلة.
6. افتح **Firestore Database → Create database** وأنشئ قاعدة بيانات. اختر الموقع الجغرافي المناسب لكم؛ لا توجد حاجة إلى إضافة بيانات يدوية الآن.
7. في **Firestore Database → Rules** الصق محتوى `firestore.rules` كاملًا. استبدل `father@example.com` و`mother@example.com` و`brother@example.com` بالبريد الإلكتروني الحقيقي للحسابات التي أنشأتها، ثم اضغط **Publish**. لا تنشر القواعد وهي تحتوي عناوين المثال.
8. من **Authentication → Settings → Authorized domains** تأكد أن نطاق موقع GitHub Pages موجود. للموقع الرئيسي لحساب GitHub يكون عادةً `USERNAME.github.io`، ولرابط مشروع Pages يكون اسم المضيف أيضًا `USERNAME.github.io`. أضفه إذا لم يكن موجودًا.

## B) النشر عبر GitHub Pages

1. أنشئ مستودعًا عامًا جديدًا على GitHub مثل `family-shop-prices`، أو استخدم مستودعًا خاصًا بالمشروع.
2. ارفع **محتويات هذا المجلد** إلى المستوى الرئيسي للمستودع: `index.html`, `style.css`, `app.js`, `firebase-config.js`.
3. افتح **Settings → Pages**. اختر **Deploy from a branch** ثم الفرع `main` والمجلد `/ (root)` ثم Save.
4. انتظر اكتمال النشر وافتح رابط الموقع الظاهر في Settings → Pages.
5. افتح الموقع من الهاتف، وسجّل الدخول بأحد الحسابات التي أنشأتها في Firebase Authentication.

## ج) إعداد العملة

في نهاية `index.html` يوجد السطر:

```js
window.SHOP_CURRENCY = 'ل.س';
```

بدّل `ل.س` إلى العملة التي تستخدمونها في الدكان إذا لزم ذلك، ثم احفظ الملف.

## د) ملاحظات أمان مهمة

- لا تضع كلمة مرور أو مفتاح خدمة إداري (Service Account) داخل ملفات الموقع.
- إعداد Firebase للويب يظهر في الواجهة وهذا طبيعي؛ الحماية الحقيقية تأتي من قواعد Firestore المقيدة بعناوين العائلة أعلاه.
- أنشئ الحسابات يدويًا من Firebase Authentication فقط. لا تضف تسجيلًا عامًا ما دمت تستخدم هذه القواعد.
- إذا تغير بريد أحد أفراد العائلة، عدّل قائمة البريد في قواعد Firestore وانشر القواعد الجديدة.
- GitHub Pages يستضيف الواجهة فقط؛ تخزين ومزامنة الأسعار يتمان في Firebase.
- هذه النسخة لا تنفذ حساب المخزون أو المبيعات أو الأرباح؛ إنها لإدارة أسماء المنتجات وأسعارها ووحدات البيع والتصنيفات والملاحظات.

## استكشاف الأخطاء
- تظهر رسالة `بقي ربط Firebase`: بيانات `firebase-config.js` ما زالت تجريبية أو غير مكتملة.
- لا يمكن تسجيل الدخول: تحقق من تفعيل Email/Password وأن الحساب أُنشئ من Authentication → Users.
- تسجيل الدخول ينجح لكن المنتجات لا تظهر: تحقق من نشر قواعد `firestore.rules` وأن البريد المسجل موجود حرفيًا ضمن قائمة العائلة.
- الصفحة قديمة بعد التعديل: حدّثها بقوة (`Ctrl + F5`) وانتظر انتهاء Pages deployment.
